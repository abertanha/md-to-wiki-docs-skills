## O que "byte-idêntico por geminho" significa aqui

Não existe golden `.ps1` anterior. A linguagem de byte-identidade do Success Criterion 2 do ROADMAP descreve um baseline que nunca foi capturado — o `tests/fixtures/golden-ps1/` não está no disco e a Phase 1 registrou a dívida em `01-03` e no manifesto. Portanto:

- a captura desta fase É o baseline, e o comportamento pós-refactor (incluindo a decisão de encoding do D-15 e a convergência da URL de rodapé) é o que fica congelado;
- a barra de byte-identidade que esta fase tem de PRESERVAR é a do lado `.sh`, que existe e está commitada — `tests/fixtures/golden-sh/` não muda um byte nesta fase;
- a partir daqui, byte-identidade `.ps1` passa a ser um critério de verdade e não mais aspiracional: qualquer mudança futura de chrome em `.ps1` aparece como diff.

Essa distinção precisa ficar escrita no manifesto, junto com a data e o SHA da captura, para que um contribuidor futuro saiba qual forma de bytes é intencional (o manifesto já tem a seção "Proibição de edição manual do golden" para exatamente isso).

## Pins da invocação canônica da cadeia `.ps1`

A cadeia `.ps1` NÃO é estruturalmente igual à `.sh` (ver os não-objetivos do plano `04-03`), então os pins divergem em dois pontos que precisam ficar registrados — sem isso a captura não é reprodutível.

| Pin | Valor | Por quê |
|-----|-------|---------|
| Interpretador | `pwsh -NoProfile -NonInteractive -File` | Perfil de usuário pode alterar default de encoding e de `ErrorActionPreference`; sem `-NoProfile` a captura depende da máquina de quem capturou |
| `PROJECT_NAME` / `AUDIENCE` / `SOURCES` | `TestProject` / `general` / `.specs` | Idênticos aos pins da cadeia `.sh` já registrados no manifesto |
| Diretório-base de features do index | `.specs/features` | DIVERGE do pin `.sh` (`docs/specs/features`): `generate-mkdocs.ps1` não copia a árvore de specs para dentro de `docs/`, divergência estrutural preservada pelo D-19 |
| Superfície PDF | o arquivo `specs-book.md` produzido pelo script, e o status de saída diferente de zero do script é TOLERADO | Exceção D-10, já antecipada no manifesto: o gêmeo não tem fallback markdown para o PDF publicável, então num host sem engine ele grava o livro e encerra com erro. O livro é o golden; o erro é o comportamento correto e esperado nesse host |
| Cwd da captura | `mktemp -d` fora de qualquer repositório git | `generate-mkdocs.ps1` lê a URL do remoto `origin`; capturar dentro do repo vazaria essa URL para o golden (T-04-08) |
| Locale | `LC_ALL=C.UTF-8`, fixado pelo harness antes de qualquer perna | Mesmo motivo do lado `.sh`: estabilidade de collation e de tratamento de acento entre captura e diff |
| Máscara de data | a mesma regex ISO 8601 já usada pelo harness, aplicada simetricamente | Cobre o rodapé do index e o rodapé datado do livro do PDF, os dois sítios datados do lado `.ps1` já inventariados no manifesto |
