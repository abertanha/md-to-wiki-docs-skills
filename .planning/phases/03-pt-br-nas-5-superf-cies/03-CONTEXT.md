# Phase 3: pt-br nas 5 Superfícies - Context

**Gathered:** 2026-09-29
**Status:** Ready for planning

<domain>
## Phase Boundary

Phase 3 entrega o catálogo `pt-br` completo (paridade de keyset com `en.lang`), a migração de `to-pdf.sh`, `to-dokuwiki.sh` e `templates/swagger-ui.html` para consumo do catálogo por lookup, o locale projetado em cada consumer (`theme.language: pt-BR` no mkdocs.yml, `-M lang=pt-BR -M toc-title=Sumário` no pandoc, `lang` no HTML do Swagger), e o gate de grep que garante zero saída mista nas cinco superfícies publicáveis.

Fora do escopo: gêmeos `.ps1` (Phase 4), glossário anti-calque e prosa dos agents (Phase 4), wiring do harness no fluxo de release (Phase 4), mais locales além de `en`/`pt-br` (v2).

</domain>

<decisions>
## Implementation Decisions

### Assinatura dos scripts novos (`to-pdf.sh`, `to-dokuwiki.sh`)

- **D-01:** `output_lang` entra como **segundo argumento posicional**, antes dos arquivos de entrada:
  - `to-pdf.sh <output.pdf> <output_lang> <file1.md> [file2.md ...]`
  - `to-dokuwiki.sh <output_dir> <output_lang> <file1.md> [file2.md ...]`
  - Mesmo padrão da Phase 2: posicional obrigatório, sem default no script. — **Reversibility:** costly — os agents `format-pdf.md` e `format-dokuwiki.md` precisam atualizar todos os call sites; gêmeos `.ps1` na Phase 4 replicam a nova assinatura.
- **D-02:** Bootstrap em `to-pdf.sh` e `to-dokuwiki.sh` segue exatamente o padrão D-09 da Phase 2: `(1) ler output_lang com ${2:?...}, normalizar com tr 'A-Z' 'a-z', (2) case allowlist en|pt-br ANTES de montar path, (3) derivar SCRIPT_DIR, montar CATALOG, checar [ -f "$CATALOG" ], (4) set -a; . "$CATALOG"; set +a, (5) gate fail-closed up-front com :? para todas as chaves expandidas`.
- **D-03:** `format-pdf.md` e `format-dokuwiki.md` atualizam o call site do script companion para incluir `$OUTPUT_LANG` como segundo posicional. A variável vem do `CONTEXT.md` do projeto via dispatch prompt (já estabelecido na Phase 1). — **Reversibility:** costly — agentes são contrato publicado.

### Catálogo `pt-br.lang`

- **D-04:** Arquivo `templates/lang/pt-br.lang` com o mesmo key-set de `en.lang` (33 chaves atuais + `dokuwiki_readme_*` com o esquema D-06 abaixo). Paridade verificada pelo gate de keyset do `tests/fail-closed.sh` — a suite existente já tem `keyset_equality`; a chave `pt-br.lang` é adicionada ao probe. — **Reversibility:** reversible.
- **D-05:** Valores do catálogo `pt-br.lang` seguem o glossário do CLAUDE.md (seed do glossário): `site_name_suffix='— Especificações'`, `nav_home='Início'`, `section_quick_start='Início Rápido'`, etc. Termos consagrados que ficam em inglês: `Stack`, `Roadmap`, `Design`. `cell_absent` é `—` (mesmo valor — sem tradução). `generated_by` traduz a frase: `'Gerado por [md-to-wiki](https://github.com/abertanha/md-to-wiki-docs-skills) — %s'`.
- **D-06:** Chave `pdf_toc_title` entra **somente** no `pt-br.lang` (valor `'Sumário'`) e não tem equivalente em `en.lang` — a flag `-M toc-title` não é passada ao pandoc no branch `en` (comportamento atual preservado). A ausência da chave em `en.lang` é documentada com comentário no arquivo. O gate de paridade do `fail-closed.sh` usa uma allowlist de chaves `pt-br`-exclusivas para não falhar nesse caso.

### `dokuwiki_readme` multilinhas

- **D-07:** O bloco de 6 linhas do README do DokuWiki é representado no catálogo como **3 chaves por seção semântica**:
  - `dokuwiki_readme_heading` — heading da seção (ex.: `'DokuWiki Import Instructions'` / `'Instruções de Importação DokuWiki'`)
  - `dokuwiki_readme_steps` — bloco dos 4 passos numerados como texto único com `\n` literais entre as linhas (ex.: `'1. Copie...\n2. Acesse...\n3. Clique...\n4. Verifique...'`)
  - `dokuwiki_readme_footer` — linha de rodapé (`'Generated by md-to-wiki skill set'` / `'Gerado pelo conjunto de skills md-to-wiki'`)
  O script monta o bloco com `printf '%b\n'` sobre `$dokuwiki_readme_steps` para expandir os `\n` literais. — **Reversibility:** costly — a Phase 4 replica o esquema nos gêmeos `.ps1`; renomear as chaves depois exige coordenar ambos os lados.
- **D-08:** O heredoc de `to-dokuwiki.sh` que hoje escreve o bloco diretamente é substituído por lookups das 3 chaves; o resultado final deve ser byte-idêntico ao bloco `en` atual quando `output_lang=en`. O golden da Phase 1 é a barra de verificação.

### `lang` no Swagger

- **D-09:** O template `templates/swagger-ui.html` ganha um terceiro placeholder `{{LANG}}` no atributo `lang` da tag `<html>`: `<html lang="{{LANG}}"`. — **Reversibility:** reversible — mudança local no template.
- **D-10:** `format-swagger.md` injeta o valor projetado do idioma (`pt-BR` para pt-br, `en` para en) via sed no mesmo passo que substitui `{{PROJECT_NAME}}` e `{{OPENAPI_YML}}`. O valor projetado é `pt-BR` (BCP 47 maiúsculo) — a normalização de locale acontece uma vez, neste ponto de uso.
- **D-11:** O chrome do bundle Swagger UI (botões "Authorize", "Try it out") permanece em inglês — sem i18n oficial upstream (issue #472 aberta). Isso fica documentado no CONTEXT.md do projeto. Somente `<title>`, `lang` e eventuais headings do template own são localizados.

### `theme.language` no MkDocs

- **D-12:** `generate-mkdocs.sh` emite `language: pt-BR` sob `theme:` somente quando `output_lang=pt-br`. Com `output_lang=en` a chave é omitida (comportamento atual — o default do Material é `en`). A emissão é condicional no script via `case "$OUTPUT_LANG"` — não é uma chave de catálogo (é configuração de consumidor, não rótulo de chrome). — **Reversibility:** reversible.
- **D-13:** O pandoc em `to-pdf.sh` recebe `-M lang=pt-BR -M toc-title="$pdf_toc_title"` somente no branch `pt-br` do `case`. O assert estrutural (sem engines) verifica a presença dessas flags na saída do comando montado, não na execução real.

### Gate de zero saída mista

- **D-14:** Gate grep por superfície: após geração com `OUTPUT_LANG=pt-br`, um script de probe percorre cada saída e verifica que nenhum rótulo `en` hardcoded aparece. A allowlist do glossário (`Stack`, `Roadmap`, `Design`) é passada como exceções. O gate é parte do `tests/fail-closed.sh` (extensão do harness existente) ou um script separado `tests/no-mixed-output.sh` — a decisão de estrutura fica com o planner. O critério de completion é exit 0 com zero matches fora da allowlist.

### Proibições (herdadas + novas)

- Nenhum golden de `tests/fixtures/golden-sh/` é reescrito nesta fase
- Nenhum default de idioma no script; nenhum env var de idioma lido
- Nenhuma transformação de case em runtime sobre chrome (nenhuma variável de catálogo atravessa o sed de title-case)
- Nenhuma dependência nova de runtime
- Nenhum heredoc convertido para a forma `<<'EOF'` (bloqueia expansão das variáveis de catálogo)
- `pdf_toc_title` NÃO entra em `en.lang` — inventar um valor quebra a barra byte-idêntica

</decisions>

### Reusable Assets

- `scripts/generate-index.sh` — padrão completo de bootstrap de catálogo (normalização → allowlist → SCRIPT_DIR → CATALOG check → source → gate fail-closed up-front); copiar verbatim em `to-pdf.sh` e `to-dokuwiki.sh`

- `agents/format-mkdocs.md` — modelo de como `$OUTPUT_LANG` é transmitido como posicional no dispatch prompt; replicar em `format-pdf.md` e `format-dokuwiki.md`

### Established Patterns

- Bootstrap posicional obrigatório (`${N:?...}`) sem default no script — padrão de toda a cadeia
- Gate fail-closed up-front com `:?` antes de qualquer byte de output — CHROME-03
- `sed` de title-case isolado: `s/-/ /g; s/\b\(.\)/\u\1/g` — nenhuma variável de catálogo atravessa esse pipeline
- Emissão aditiva condicional: chave `language: pt-BR` emitida só no branch `pt-br` do `case` (análogo ao que `generate-mkdocs.sh` já faz para outras emissões condicionais)
- `printf '%b\n'` para expandir `\n` literais de valores de catálogo — necessário para `dokuwiki_readme_steps`

### Integration Points

- `templates/lang/pt-br.lang` → todos os scripts migrados nesta fase: sourced com `set -a; . "$CATALOG"; set +a`
- `templates/swagger-ui.html` → `agents/format-swagger.md`: novo placeholder `{{LANG}}` injetado via sed junto com `{{PROJECT_NAME}}` e `{{OPENAPI_YML}}`
- `tests/fail-closed.sh` → `templates/lang/pt-br.lang`: probe de paridade verifica que o keyset de `pt-br.lang` ⊇ keyset de `en.lang` (exceto allowlist)

<specifics>
## Specific Ideas

- `pdf_toc_title` é chave assimétrica: existe só em `pt-br.lang` (`'Sumário'`), ausente em `en.lang`. Documentar com comentário `# pt-br exclusiva — en não passa -M toc-title (comportamento atual preservado)` em ambos os arquivos (no `pt-br.lang` como inline na chave, no `en.lang` como comentário de ausência intencional).
- O gate de keyset usa diff dos nomes de chave extraídos por `grep -o '^[^=]*'` dos dois arquivos; a allowlist de pt-br-exclusivas (`pdf_toc_title`) é passada como exceção explícita no script — não silenciada por default.
- Wart do `to-pdf.sh` a preservar: se pandoc não estiver disponível, o script emite o markdown intermediário e não falha — o golden captura esse comportamento; a refatoração não pode introduzir exit antecipado antes do wart.
- O bloco `dokuwiki_readme_steps` em inglês é: `'1. Copy the contents of \`data/\` into your DokuWiki'\''s \`data/\` directory\n2. Go to your DokuWiki Admin → Extension Manager\n3. Click "Load" to refresh the page index\n4. Verify pages under the specs namespace'` — aspas simples no possessivo `DokuWiki's` exigem fechar-inserir-reabrir (`'\''`).

</specifics>
